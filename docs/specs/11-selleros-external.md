# 11 SellerOS: the external agent

Code: `external/selleros/` (its own `pyproject.toml`). Task: T17.

## 1. Story

SellerOS is a fictional third-party company. It sells repricing and stock tools to small marketplace sellers. Its agent talks to the marketplace's agents over A2A, like two companies' systems would.
It knows things the platform does not: each seller's repricer rules, price floor, unit cost, supplier ETAs.
The platform knows things SellerOS does not: Buy Box results across all sellers, search rank, hijackers.
Together they explain S6. In S8 (the live demo) SellerOS answers "No, it was a mistake" from `price_intent_check` verdict `likely_error`, then reverts the price as the seller's fix. SellerOS also receives alerts and acts on them (pauses a repricer, reverts a manual price).

## 2. Isolation rules (checked by a test)

- `external/selleros` must not import `eye` (test: grep the package for `import eye` / `from eye`; and run it in its own venv).
- It does not read `data/world.duckdb`. It reads only `external/selleros/data/sellers.json`.
- It does not call the core API. It only answers A2A requests and receives alerts.
- It has its own copy of the agent runtime (copied from `src/eye/llm/runtime.py` in T17; the duplicate is intended — it is a different company).

## 3. Data (`external/selleros/data/sellers.json`)

Generated by the simulator at `eye-sim generate` (T02 writes it; the simulator is the only place that knows the private attributes).

```json
{
  "generated_for_seed": 42,
  "sellers": [
    {
      "seller_id": "S-03",
      "customer_of_selleros": true,
      "repricer": {"mode": "beat", "undercut_pct": 1.0, "floor": null, "status": "active"},
      "skus": [{"sku": "E02", "unit_cost": 96.0, "stock_policy_days": 3, "supplier_eta_days": 4}],
      "price_history": [{"ts": "...", "sku": "E02", "price": 131.5, "source": "repricer"}]
    }
  ]
}
```

- Customers of SellerOS: the 24 small sellers (not S-99, not large sellers).
- `price_history`: the simulator appends the seller's own price changes at each step (only its own offers). `source` is `repricer` or `manual`. A missing `source` means `repricer`. Only S8 writes `manual` (T27). In live mode the simulator writes this file every sim hour (atomic write: temp file + rename). SellerOS re-reads it on each request.

## 4. Skills

| Skill id | Input | Output (`SpecialistResponse` findings) |
|---|---|---|
| `repricer_status` | seller_ids or skus | mode, floor, last 24 h price path, number of price changes |
| `below_cost_check` | skus or category | sellers whose current price < unit cost; margin per unit |
| `supplier_eta` | seller_ids or skus | expected restock dates |
| `price_intent_check` | seller_ids and skus | per offer: last price change (ts, old, new, `source`), unit cost, verdict `intended` or `likely_error` (rule: `source = manual` and new price < unit cost → `likely_error`) |
| `receive_alert` | `SellerAlert` | `SellerAlertAck` with actions taken |

Alert handling: for each seller in the alert whose repricer has `floor = null`, SellerOS sets `status: "paused"` in its own state (in memory + a `actions.jsonl` log) and returns the action list. If `recommended_action` asks to revert a manual price and `price_intent_check` gives `likely_error` for the seller's SKUs in the alert, SellerOS logs `reverted manual price for <seller> on <skus>` and returns that action. The simulator does not read this state (keeping the dependency one-way). For the demo, the UI shows the ack text, and the demo runner calls `clear(S8)` to model the seller's fix.

## 5. Agent

- A2A server on port 8300, Agent Card name "SellerOS Partner Agent", description "Third-party repricing and inventory assistant for small marketplace sellers".
- LLM agent with tools over `sellers.json` (`get_repricer`, `get_costs`, `get_price_history`, `get_supplier_eta`, `pause_repricer`), effort `medium`, max steps 6.
- Privacy rule in its prompt: share per-seller facts only about sellers named in the request or about SKUs in the request; never return the full customer list.
