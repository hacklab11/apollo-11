# T21 Web UI on mock data

Owner: P3 (runs a Devin or Claude Code session; checks the result in the browser) · Depends on: T00 · Blocks: T22

## Goal
The full one-page UI, working in mock mode, before the backend exists.

## Read first
`docs/specs/web.md` §3 (layout, visual rules, mock mode). `docs/specs/contracts.md` (shapes of the mock JSON). `web/mock/*.json`.

## Files you own
`web/index.html`, `web/app.js`, `web/styles.css`, `web/README.md`.

## Do not touch
`web/mock/` (generated by T00), any Python code.

## Steps (for the coding agent)
1. Plain HTML + JS modules + CSS. Cytoscape.js and Chart.js from a CDN with pinned versions. No build step, no framework.
2. All panels from 13 §3.1, all visual rules from §3.2, mock mode from §3.3 (`?mock=1`).
3. One `api.js`-style module with one function per endpoint, so T22 only changes the base behaviour (mock vs live).
4. Open with `python -m http.server -d web 5500` and `http://localhost:5500/?mock=1`.

## Steps (for P3, the reviewer)
1. Open the page in mock mode. Go through the checklist below. Write each failure as a short sentence back to the coding agent.
2. Check that the S7 incident tells the story clearly to someone who did not build it. Ask a team member to read it for 30 seconds and say what happened.

## Done when (checklist in the PR)
- [ ] Graph shows ≥ 12 nodes; formula vs causal edges look different; clicking a node shows its chart with the expected band.
- [ ] Incidents list with tabs; S7 and S6 mock incidents open; verdict badges have text.
- [ ] Trail timeline shows actor, tool, summary, reason; SellerOS steps marked "external".
- [ ] Contributions bars with signed % and striped "planned" row.
- [ ] Live feed scrolls with replayed events.
- [ ] Add-metric modal shows the mock `AddMetricResult`.
- [ ] Chat panel shows the mock answer with collapsed tool calls.
- [ ] Keyboard: Tab reaches every button; focus is visible.
